# AGENTS.md

Bijli Saathi: unofficial Android app (Expo SDK 57, React Native, Expo Router) for UPPCL smart
meters. The phone calls UPPCL directly with reverse-engineered APIs. No backend of our own, no database;
never log, store or send credentials/tokens/account data anywhere but UPPCL and the OS keystore.

## Commands (bun only: never npm/pnpm, corepack would inject a packageManager field)
- Install: `bun install`
- Type check: `bun run typecheck` (`tsc --noEmit`; `tests/` is excluded)
- Test (all): `bun test` · single file: `bun test tests/sanity.test.ts`
- PII/secret scan (CI runs it): `scripts/scan-pii.sh` (set `PII_PATTERNS` to the maintainer's list for the full scan)
- Prove dev tools are removable: `scripts/remove-dev-tools.sh` (destructive: run on a copy, as CI does)
- "UPPCL or us?": `bun scripts/check-upstreams.ts <account-number>` — read-only status of UPPCL SMART,
  bill portal and 1912 portal. `CCB_ISE_SE_503` = UPPCL's billing backend is down.
- Run on a device/emulator: `bunx expo run:android` (Android SDK + JDK 17; first build ~10 min)
- iOS on a real cloud iPhone: `python scripts/ios-smoke.py <app.ipa> [--sample]` (needs `pip install Appium-Python-Client`,
  `BSTACK_USERNAME`/`BSTACK_ACCESS_KEY`; without `--sample` it signs in with `UPPCL_USER`/`UPPCL_PASS`, masked).
  Screenshots land in git-ignored `qa/ios/`. Read-only: opens Pay and the complaint sheet, never pays or files.
- Release: bump `expo.version` (and `android.versionCode` for a new version) in `app.json`, push tag
  `vX.Y.Z` matching it. `.github/workflows/release.yml` builds, signs and uploads the APK; re-pushing the
  same tag or re-running the workflow overwrites the asset.
  The in-app update check (`src/github.tsx`) reads the latest Release: keep tags `vX.Y.Z` = app.json version,
  exactly one `.apk` asset per release, and bump the version for any build users should be offered.

## Structure
- `app/` Expo Router screens. `src/` app-only code (`boot.ts` wires the platform seam; `theme.ts` tokens; `ui.tsx` primitives).
- `shared/` (imported as `@shared/*`): the phone-free half — API client + SWR hooks + types (`api.ts`), bill
  payment (`payment.ts`), 1912 complaints (`complaints.ts`: status, filing, SMS/call channels), crypto, insights,
  helpers (`utils.ts`). `platform.ts` is its only seam to the phone; `src/boot.ts` fills it.
  This repo is the source of truth (the web project's copy is frozen).
- Complaint flows: the two-tap "No power?" sheet is `src/report.tsx`; the full form is `app/report.tsx`.
- `messages/{en,hi}.json`: strings under `"app"` (plus `"login"` field labels).
- `src/dev/`: dev-only fake-data test scenarios. `tests/`: `bun test` suites. `docs/`: upstream API notes.

## Conventions
- Before writing a helper, grep for one: `rupees`, `kwh`, `parseUppclDate`, `billingPeriod`, `toNum`, `mean` exist (`shared/utils.ts`).
- UI primitives live in `src/ui.tsx`: `Screen` (with optional pinned `footer`), `Card`, `Button`, `Field` (every text box),
  `Sheet` + `Choices` (mobile pickers), `Skeleton`. Use them; don't style a raw `TextInput`.
- SWR: import `mutate` from `@shared/api`, **never from "swr"**. The app's cache is an SWRConfig provider; swr's own
  `mutate` changes a different cache no screen reads (sign-in/out then waited for the 60 s /health poll).
- New upstream endpoints go in `shared/api.ts`, through `send()` (it tags errors with whose side failed).
- Every user-visible string goes in both `messages/en.json` and `messages/hi.json`.
- Colours come from `src/theme.ts` tokens; re-check contrast when changing them.
- Dev tools stay in `src/dev`. Main code may touch them only via one-line hooks tagged `@dev-tools`,
  behind `__DEV__`; each tagged line must be deletable on its own (CI job `dev-tools-removable`).
- Tests go in `tests/`, never next to app code; no test helpers in app code. Mock native modules with
  `mock.module` (see `tests/sanity.test.ts`).
- Expo packages use `~57.0.0` ranges on purpose: the maintainer's package guard refuses very new releases.

## Gotchas
- `android/` and `ios/` are generated by `expo prebuild` from `app.json`; change `app.json`, never native folders.
- `fileSupplyComplaint` (shared/complaints.ts) files a REAL complaint with UPPCL 1912. Never call it in tests or QA;
  test up to `prepareSupplyComplaint`/`chooseSubstation` (read-only lookups + validate). Use only your own account.
- Complaint status: `shared/complaints.ts` calls UPPCL's 1912 portal (Appsavy) at `1912.uppcl.org` directly;
  its session cookies ride the phone's native cookie jar (a Mac test needs a cookie-jar fetch). The old host
  appsavy.com/coreapps stopped answering in Oct 2026. Everything is direct to UPPCL; no server of ours.
- Public UPPCL constants (API key, bill-portal appServiceKey, Appsavy key) are not secrets but are kept
  as-is/assembled from fragments so secret scanners don't flag them. Don't copy them into new files.
- Never commit real account numbers, phone numbers, names, addresses, JWTs, keystores or screenshots of a real account.
- Session data lives in one AES-GCM file (`vault-v1.bin`) whose key is in the OS keystore (`src/boot.ts`).
  Don't add SecureStore reads on the startup path: each one is a slow hardware decrypt on old phones.
- A corp gitleaks hook blocks commits that re-add `shared/api.ts`'s public constants (e.g. moving the file).
- Hermes is strict about dates: parse UPPCL dates with `parseUppclDate`, never `new Date(str)`.
- Empty states must check SWR `isLoading` first: some UPPCL calls take ~10 s.
- UPPCL API quirks: see `docs/api-reverse-engineering.md` and `docs/payment-reverse-engineering.md`.

## Working on an issue
1. Reproduce: a failing test in `tests/` for pure logic, or a dev test scenario (Settings → Developer) for screens.
2. Fix with minimal churn; reuse helpers in `shared/`.
3. `bun run typecheck` and `bun test` must pass.
4. Branch `fix/<short-desc>` or `feat/<short-desc>`; conventional commit message.
5. PR description: root cause, what changed, how you verified.
